# Проверка с настоящим API-ключом

1. Создайте ключ в своём аккаунте на https://platform.openai.com/api-keys. Нужен доступ к API и выбранной модели; запросы используют лимит API-аккаунта.
2. Клонируйте репозиторий, откройте терминал в родительском каталоге проекта и выполните:

```bash
cd cardcraft-b2b
python3 scripts/check_live.py
```

3. На запрос `OpenAI API key (ввод скрыт):` вставьте ключ и нажмите Enter. Отсутствие символов на экране нормально. Ключ остаётся в памяти процесса и не записывается скриптом на диск. Если ключ уже передан через `OPENAI_API_KEY`, запроса не будет.
4. Дождитесь двух строк `OK`, для манометра и синтетического измерителя температуры. Должно быть `mode=live`. Если возникла ошибка, прогон не завершён; ранее сохранённый файл сам по себе не доказывает успех текущего запуска.
5. Откройте `output/live/manometer.md` и `output/live/demo-incomplete.md`. Рядом лежат JSON с исходными ссылками, планом модели, предупреждениями и счётчиками.

Выполняются два реальных вызова, при временных ошибках каждый может повториться до трёх раз. Ключ не нужно отправлять в чат. Для следующего запуска его можно ввести снова. Скрипт не меняет demo-примеры и не отправляет файлы на GitHub.

## Что проверить в результате

- `meta.mode` — `live`, модель соответствует выбранной в `OPENAI_MODEL` (по умолчанию `gpt-4o-mini`).
- Заголовок не длиннее 70, описание — 800–1200 символов.
- В назначении нет фразы, которую модель неверно приняла за применение прибора.
- Каждое техническое значение совпадает с входом; нет новых обещаний совместимости, защиты или сертификации.
- Вопросы менеджеру соответствуют задаче, неизвестные поля видны.
- Синтетический пример не выдаётся за товар работодателя.

## Если возникла ошибка

- `api_auth`: ключ отклонён или у него нет нужного доступа. Проверьте ключ и права проекта.
- `api_unavailable` с 429: проверьте лимиты/доступные средства API-аккаунта; причина может быть в частоте запросов или квоте. Сырые ответы провайдера намеренно не выводятся.
- `api_unavailable` с 400/404: проверьте название модели и её поддержку Chat Completions со Structured Outputs.
- `api_timeout`: проверьте подключение к API и повторите позже.
- `invalid_model_output`: модель вернула неподходящий план; это не успешная карточка, несмотря на доступность API.

Команды альтернативного ввода через переменную окружения приведены в README. Файл `.env` сам по себе приложением не читается.

Официальная инструкция по ключам и окружению: https://developers.openai.com/api/docs/quickstart
